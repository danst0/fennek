# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Projekt

**Fennek** — Multi-App-Handheld-Firmware für das **LilyGO T-Deck Pro V1.1** (ESP32-S3, 8 MB PSRAM), PlatformIO/Arduino. (Eigenständiges Projekt `fennek` (Remote `danst0/fennek`); entstand in Anlehnung an den Meck-Fork `pelgraine/Meck`. Version: `FENNEK_VERSION` in `src/config.h`, Log-Präfix `[FENNEK]`. NVS-Namespace `fennek` und SD-Cache `/.fennek` — Altbestände aus der Meck-Ära werden beim Boot automatisch migriert.) Launcher-Homescreen + Apps: **Musik** (MP3-Player), **Hörbuch**, **Lesen** (TXT/EPUB), **Mesh** (schlanker MeshCore-Client), **Spiele** und **Dateien** (Web-Dateiverwaltung der SD über WLAN). Fokus: flüssige Bedienung (Touch + Tastatur) und stotterfreie Wiedergabe; Hintergrund-Audio läuft über App-Wechsel hinweg. Code-Kommentare, Serial-Ausgaben und Doku sind **deutsch**; alle Textausgaben laufen über `gui::print` (UTF-8 → CP437, Umlaute!).

- Aktiver Code in `src/` (einzige Build-Env: `fennek`).
- `lib/meshcore/` + `lib/ed25519/` — vendored MeshCore-Stack (Subset des alten Meck-Codes) für die Mesh-App.
- Die alte MeshCore-/Meck-Firmware (vormals `archive_legacy/`) liegt in der **Git-Historie** — Referenz für hardware-verifizierte Pin-/Init-Sequenzen und Quellbasis der Vendor-Kopien (`git show <commit>:archive_legacy/...`).
- `boards/` — enthält nur noch `t-deck_pro.json` (Partition `default_16MB.csv`: 6,5-MB-App-Slots, 3,4 MB SPIFFS, 20 KB NVS).

## Build & Flash

```bash
pio run -e fennek              # bauen
pio run -e fennek -t upload    # flashen (USB-C an /dev/ttyACM0, 921600 Baud)
pio device monitor -b 115200      # serielles Boot-Log (mit Exception-Decoder)
```

Keine Unit-Tests/Lint; Verifikation am Gerät über das Boot-Log (`[FENNEK] …`/`[MESH] …`-Zeilen). Die Firmware bootet und läuft vollständig **ohne SD-Karte** (Apps zeigen „Keine SD-Karte“ + „Erneut suchen“).

Debug-Flags (als `-D` ergänzen):
- `AUDIO_DEBUG_GAP` — Stotter-Test: loggt `[GAP] … maxGap=…ms`; muss unter der I2S-DMA-Tiefe (~90 ms) bleiben.
- `PLAYLIST_SELFTEST` — schreibt/scannt/löscht eine Test-`.m3u` beim Boot.
- `MESH_SMOKE_TEST` — initialisiert das Mesh-Radio beim Boot (Verifikation ohne UI).
- `GAMES_SMOKE_TEST` — klickt beim Boot alle vier Spiele synthetisch durch (Draw-Pfade + Schach-KI-Task; Verifikation ohne Hand am Gerät).
- `SLEEP_WAKE_TEST` — verkürzt den Standby-Timer-Wake (Akku-% aufs Schlafbild) von 1 h auf 60 s.
- `BATTLOG` — Debug-Akku-/Aktivitäts-Logger (`services/battlog.*`): schreibt pro Ereignis (App-Wechsel, Audio-Track, Mesh-Radio an, WLAN an/aus, Standby/Wake) **und** alle 60 s eine Akku-Probe nach `/.fennek/battery.log` (Zeitstempel + %/mV/lädt? + WLAN-/Mesh-Status; PSRAM-Ring, gedrosselt + vor dem Standby nach SD, über WebFM herunterladbar). Bewusst abschaltbar: ohne das Flag kompilieren alle `BATTLOG_*`-Aufrufe zu Nichts; zum Ausbau die `platformio.ini`-Zeile entfernen und `battlog.*` + die Aufrufe löschen.

## Toolchain ist bewusst gepinnt — nicht aktualisieren

`espressif32@6.11.0` (Arduino-ESP32 2.0.17 / IDF 4.4) und `ESP32-audioI2S#2.0.6` sind hardware-verifiziert. Dazu: RadioLib ^7.3 (`RADIOLIB_GODMODE=1` nötig für `spreadingFactor`-Zugriff), rweather/Crypto, densaugeo/base64. Versions-Upgrades nur auf ausdrücklichen Wunsch.

## Architektur — die Anti-Stotter-Invarianten

Kernproblem der Hardware: **E-Ink, SD-Karte und LoRa-SX1262 teilen sich denselben SPI-Bus** (HSPI, SCLK 36 / MOSI 33 / MISO 47).

```
Core 0:  Audio-Decode-Task (Prio 4) ── audio.loop() ──────┐
Core 1:  Arduino loop() ── appmgr (Eingaben/E-Ink/Apps) ──┼─ g_spiMutex (core/board.h)
Core 1:  Mesh-Pumpe (mesh_app::background → spiLock) ─────┘
```

Diese Invarianten dürfen nicht brechen:

1. **Jeder SPI-Zugriff (SD, E-Ink, LoRa) läuft unter `spiLock()`/`spiUnlock()`.**
2. **Alle `audio.*`-Aufrufe der ESP32-audioI2S-Lib nur im Audio-Task** (UI sendet Kommandos über die Queue in `services/audio.cpp`).
3. **SPI-Mutex-Freigabe während der E-Ink-BUSY-Phase** (`setBusyCallback` in `core/display.cpp`) — sonst läuft das I2S-DMA leer.
4. **256 KB PSRAM-Read-Ahead** (`audio.setBufsize(-1, 256*1024)`).
5. **SPI bleibt auf 4 MHz** (`SPI_BUS_HZ`) — 8 MHz korrumpiert SD-Writes.
6. **LoRa-CS (GPIO 3) im Leerlauf deselektiert (HIGH)**; das Radio nutzt die **bestehende `g_spi`-Instanz** (übergeben im `Module`-Konstruktor; `P_LORA_SCLK` absichtlich NICHT definiert, sonst re-initialisiert `std_init` den Bus).
7. **E-Ink-Refreshes nur bei echter Änderung** (Dirty-Flag im appmgr); Fortschritt/Statuszeile nur als `renderRegion`-Streifen.
8. **NVS (Preferences) für Settings/Bookmarks** — interner Flash, nie der SPI-Bus. SD nur für Bulk-Caches (`/.fennek/tracks.bin`, `/.fennek/id3.bin`, `/.fennek/idx/`, `/books/.epub_cache/`) und Mesh-Daten unter `/meshcore/` (Log/Kontakt-Spiegel/Kanäle, s. mesh_client). Mesh-Identity + Kontakte führend auf SPIFFS (SD-Kontakt-Spiegel hat beim Laden Vorrang). Einmalige Migrationen vom Meck-Erbe laufen automatisch: NVS `meck`→`fennek` (settings.cpp) und SD `/.meck`→`/.fennek` (main.cpp).

## Module (`src/`)

- `config.h` — alle Pins & Konstanten (aus `archive_legacy/variants/lilygo_tdeck_pro/variant.h`).
- `core/board.*` — Power, geteilter SPI-Bus, SD-Mount (+`sdReady`), `loraPower`, `gpsPower`, `g_spiMutex`. **Ungenutzte Peripherie wird beim Boot abgeschaltet** (`powerOn()` treibt Enable LOW, `kHoldPins` hält über den Deep Sleep): **GPS-Modul** (UART RX44/TX43, `PIN_GPS_EN`=GPIO39 active-high) und **DRV2605-Vibrationsmotor-Treiber** (I2C 0x5A, `PIN_DRV_EN`=GPIO2). Das **GPS wird nur von der Maps-App** temporär versorgt (`board::gpsPower(true/false)` → Enable HIGH/LOW + `Serial1` an/aus, nur solange die App vorn ist); `enterStandby()` ruft sicherheitshalber `gpsPower(false)`, bevor `holdSleepPins()` den Pegel einfriert. Die eigene Mesh-Position (`pos`/`settings::meshPos`) wird von der Maps-App bei gültigem Fix gedrosselt nachgeführt, ist sonst ein manueller Wert. **Kein 4G-Modem** auf dieser Variante: das Modem gibt es nur auf der „4G version" (GPIO-Konflikt mit dem PCM5102A-DAC); Fennek = Audio-Variante. Die **BHI260AP-IMU** (0x28) hängt ohne eigenen Enable am Perf-Rail (für Tastatur/Touch nötig) — nicht einzeln abschaltbar, idlet aber ohne Firmware-Upload stromsparend.
- `core/display.*` — GxEPD2-E-Ink, `render(fn, full)`/`renderRegion(fn, y, h)`, BUSY-Callback, `cp437(true)`.
- `core/gui.*` — `toCp437`/`cp437For`/`print`/`printAt`/`textBounds`, `drawButton`, `drawRowText`, `Rect`.
- `core/touch.*` + `core/hyn/` — CST328 (I2C 13/14, nie vom SPI blockiert); hyn/ nicht refactoren.
- `core/keyboard.*` — TCA8418 (I2C 0x34, Polling, Sticky Shift/Alt/Sym, Key-Repeat 400/150 ms).
- `core/battery.*` — BQ27220-Fuel-Gauge (nur Lesen; Kalibrierung persistiert vom Legacy-Build).
- `core/settings.*` — NVS: Lautstärke, letzte App, Musik-Resume, Hörbuch-Bookmarks, Lesepositionen; `crc32`.
- `core/console.*` — Serial-Debug-Konsole (USB, `help`): `status`, `time`/`time set <…>`/`time sync`/`tz <POSIX-TZ>` (Uhr/Zeitzone), `mesh init`, `advert`, `public <text>`, `join <name>`/`chan <name> <txt>` (Hashtag-Kanäle), `dm <idx> <text>`, `contacts` (zeigt Kontakt-Positionen aus Adverts), `msgs`, `pos [<lat> <lon>]` (eigene Standortbake), `advert`/`advert flood` (Zero-Hop bzw. mehrhopfähiger Flood-Advert), `alarm …` (Wecker setzen/testen, s. alarmclock), `gps [sek]`/`gps scan`/`gps off` (GPS headless testen: rohe NMEA + dekodierter Fix; `scan` probiert Baudraten durch — bestätigte am Gerät 38400/MIA-M10Q), `rm <pfad>` (rekursiv löschen, eigener 512-B-Puffer für Calibre-Überlängenpfade), `wifi ssid/pass/status/start/stop`, `ollama url/model/on/off/test/flush` (Notizen via lokales LLM schönschreiben, s. notes_ai), `podcast`/`podcast feed <url>`/`podcast rm <idx>`/`podcast on|off`/`podcast sync` (Podcast-Abos + Episoden-Sync, s. services/podcast). Sende-Befehle initialisieren das Mesh bei Bedarf automatisch — Mesh-Tests, Wecker-Tests **und GPS-Tests** laufen damit komplett ohne Display; WLAN-Zugangsdaten gehen hier oder über die Settings-App.
- `core/power.*` — Knopf (kurz = Tastensperre, lang = Standby), Auto-Standby, Deep Sleep mit Schlafbild + Akku-%-Banner. **Achtung, zwei Seitenknöpfe:** OBEN = Firmware-Knopf (GPIO0), UNTEN = Hardware-Reset (RST) — ein Druck unten resettet sofort (Reset-Grund=1, Firmware sieht nichts; hat am 12.06.2026 eine lange Debug-Session gekostet). Konsole: `sleep` löst den Standby ohne Knopf aus; `status` zeigt Reset-Grund/Wake-Quelle. Vor dem **Auto**-Standby (nicht beim Langdruck) zieht `timesync::syncBeforeStandby()` bei schlechter Uhr-Qualität + vorhandenen WLAN-Daten kurz NTP nach (Gerät ist idle, Audio eh gestoppt), damit es mit frischer Uhr einschläft; `enterStandby()` sichert die Zeit ins NVS. Back-off (RTC-RAM, übersteht Schlaf) verhindert, dass ein dauernd fehlschlagender Sync bei jedem Standby den Akku kostet. Bei angestecktem USB mit offenem Serial-Port kann ein GPIO0-Druck zusätzlich die USB-JTAG-Reset-Logik triggern (Host-DTR) — Standby-Tests daher auf Akku. Wake-Quellen: Knopf (EXT1) **und** Stunden-Timer — `power::handleTimerWake()` (ganz früh in `setup()`) fährt bei Timer-Wake einen Minimal-Pfad (Power/I2C/`display::beginAfterSleep()`, kein SD/Audio/Apps), erneuert nur den Banner-Streifen (`renderRegion`; alle 12 Wakes Vollbild gegen Ghosting) und schläft sofort wieder. **Wecker-Wake:** `enterStandby()` berechnet (mit gültiger Zeitzone) per `alarmclock::nextDueEpoch()` den nächsten Weckzeitpunkt und legt ihn absolut im RTC-RAM ab; `nextWakeUs()` stellt den Timer auf `min(Stunden-Takt, bis-Wecker)`. Erkennt `handleTimerWake()` (reine UTC-Epochen-Arithmetik, ohne Zeitzone) den fälligen Wecker, gibt es `false` zurück → **Vollboot** statt Minimal-Banner, dann klingelt `alarmclock::poll()` im normalen `loop()`.
- `core/appmgr.*` — App-Lifecycle (`onEnter/onLeave/tick/background/handleInput/draw`), Statuszeile (App-Name, ♫, Akku-%), Eingabe-Polling, Dirty-Koaleszenz, Anti-Doppeltap, 30-s-Persistenz, Stepping für Bibliotheks- und ID3-Scan (beide pausieren bei aktiver Wiedergabe — SD-Zugriffe unter spiLock würden dem Audio-Task den Bus streitig machen). Tap auf Statuszeile = Home.
- `services/timesync.*` — Zeit-Koordinator (das Gerät hat **keinen** Hardware-RTC). Kanonische Uhr = **ESP32-Systemzeit** (`settimeofday`/`gettimeofday`); überlebt den Deep Sleep (RTC-Zähler läuft im Schlaf weiter), anders als die frühere `millis()`-Uhr, die die Schlafdauer verlor. MeshCore bekommt einen dünnen `SystemRTCClock`-Wrapper (in `mesh_client.cpp`). Drei Quellen, **GPS hat Vorrang**: **GPS-UTC** (`gpsSync()`, aus der Maps-App/RMC — satellitengenau; setzt die Uhr nur bei Abweichung >2 s und stempelt „frisch", `gpsFresh()` übergeht dann ~10 min lang NTP **und** Mesh), **NTP** (opportunistisch wenn WLAN via webfm läuft + einmalig vor dem Auto-Standby bei schlechter Qualität, `configTime(0,0,…)` = UTC) und **Mesh-Adverts** (`mesh_client::onExternalSync`). Sync-Häufigkeit ist an die **geschätzte Qualität** geknüpft (`estErr = gelernteDrift_ppm × Zeit_seit_Sync`; Schwelle ~5 min), nicht an einen festen Takt; die Drift wird aus aufeinanderfolgenden NTP-Syncs gelernt (NVS `cppm`). **Back-off** (exponentiell, RTC-RAM) drosselt fehlschlagende Pre-Standby-Syncs. NVS (`ltime`) ist nur Kaltstart-Fallback. **Zeitzone** (NTP/Mesh liefern nur UTC!) als POSIX-TZ in NVS (`tz`, Default Europe/Berlin inkl. DST), via `applyTimezone()` (setenv+tzset) angewandt; alle Anzeigen nutzen `localtime_r`. Getter: `now()/estErrSeconds()/isStale()/source()/qualityStr()`; Diagnose/Steuerung über Konsole `time*`/`tz` oder die Settings-App (Zeilen „Zeitzone"/„Zeit"). `poll()` im `loop()`, `begin()` nach `settings::begin()`.
- `services/audio.*` — pfadbasierte Abspiel-Queue (PSRAM-Staging + Commit), Owner-Token (Music/Book/Podcast), Shuffle/Repeat, `seekRel` (CBR-MP3), Start-Offset, Sleep-Timer. `noteTrackEnded()` (im Audio-Task, an Trackwechsel/EOF/Stop) meldet ausreichend lange gespielte Musik-Tracks an `scrobble::enqueue()`.
- `services/scrobble.*` — Navidrome/Subsonic-Scrobbling. **WLAN ⊥ Audio** (s. webfm-Regel) ⇒ kein Echtzeit-Scrobble: gespielte Tracks (Owner Music, >50 % oder >4 min) landen in einer PSRAM-Queue, `poll()` persistiert sie gedrosselt nach `/.fennek/scrobbles.tsv` (übersteht Deep Sleep). Upload gesammelt **vor dem Auto-Standby** (`flushBeforeStandby()` in `power::poll()`, neben `timesync::syncBeforeStandby()`, mit RTC-RAM-Back-off): blockendes WLAN (Audio-Stop + Mesh-Suspend wie webfm), pro Eintrag Song-ID via `/rest/search3` auflösen (Minimal-JSON, erstes Ergebnis), dann `/rest/scrobble` (Token-Auth md5 via mbedtls; http+https via `setInsecure()`). Setzt voraus, dass dieselbe Sammlung in Navidrome liegt. Konfig (NVS `nscro`/`nurl`/`nuser`/`npass`) in der Settings-App-Kategorie „Navidrome“ oder Konsole `nav url/user/pass/on/off/test`, `scrobble`/`scrobble flush`.
- `services/notes_ai.*` — Tagesnotizen automatisch „schönschreiben“ via **Ollama** (lokales LLM). Gleiche WLAN⊥Audio-Logik wie scrobble: kein Dauer-WLAN, daher Batch-Lauf **vor dem Auto-Standby** (`flushBeforeStandby()` in `power::poll()`, nach scrobble, mit RTC-RAM-Back-off). Sucht in `/notes` alle `.md` **außer der heutigen** (der noch wachsende Tagestext soll nicht mitten am Tag umformuliert werden), die seit dem letzten Polieren **geändert** wurden — Done-Liste `/.fennek/notes_ai.done` (`Dateiname<TAB>SHA256`/Zeile) speichert den Inhalts-SHA256 der polierten Fassung (mbedtls, gechunkt unter spiLock); weicht der aktuelle Hash ab (oder fehlt der Eintrag), wird neu poliert (genauer Änderungsindikator — auch längengleiche Edits triggern). Je Notiz `POST {url}/api/generate` (`stream:false`, `temperature:0.2`, fester deutscher Lektor-System-Prompt), die Antwort **ersetzt die Notiz direkt** auf der SD, dann Dateiname+neuer Hash in die Done-Liste. Pro Lauf max. 20 Notizen (WLAN kurz halten; Rest folgt nächsten Standby). JSON ohne ArduinoJson (eigener Escape + `response`-Extraktor inkl. `\uXXXX`/Surrogat→UTF-8). SD-Disziplin wie scrobble (Lesen/Schreiben gechunkt unter spiLock, HTTP nur nach spiUnlock). Läuft nur aus loop()/Konsole (Core 1) — kein Audio-Task, kein Mutex. **Hinweis:** Ollama liefert echte Umlaute (UTF-8) zurück; `gui::print` stellt sie korrekt dar, aber der Notiz-Editor (`computeLayout`, Annahme Spalte==Byte) bricht Umlaut-Zeilen minimal früh um (kosmetisch). Konfig (NVS `oai`/`ourl`/`omod`, Default-Modell `llama3.2`) in der Settings-App-Kategorie „Ollama“ oder Konsole `ollama url/model/on/off/test/flush`.
- `services/podcast.*` — Podcast-Abos + Episoden-Sync. Gleiche WLAN⊥Audio-Logik wie scrobble/notes_ai. Abos in **`/podcasts/feeds.txt`** (eine RSS-URL/Zeile, optional `URL<TAB>Name`, `#`=Kommentar; per WebFM editierbar wie `channels.txt`; beim ersten Start mit **Freakshow** (`https://freakshow.fm/feed/mp3/`) vorbelegt). Pro Feed ein Ordner `/podcasts/<slug>/` (Slug = lesbarer Host-Präfix + FNV-Hash-Suffix, kollisionsfrei) mit der **EINEN behaltenen** neuesten Folge `episode.<ext>` + `state.txt` (guid/title/file). **Sync:** verwaltet WLAN selbst (Audio-Stop + Mesh-Suspend), lädt nur den **Anfang** des (oft >1 MB großen) Feeds bis das erste `<item>` Titel/Enclosure/GUID hergibt (RSS-Parsing per Substring im Arduino-freien `apps/podcast_core.h`, host-getestet; neueste Folge = erstes `<item>`), vergleicht GUID mit `state.txt`, lädt bei Neuem die Enclosure **gechunkt nach SD** (eigene Redirect-Auflösung http↔https, Netz-I/O nach spiUnlock, Schreiben unter spiLock, `.part`→rename) und löscht ältere Audiodateien („nur letzte Folge behalten“). **Manueller Sync** (App-Button/`podcast sync`) synchronisiert alle Feeds; **Auto-Sync vor dem Auto-Standby** (`flushBeforeStandby()` in `power::poll()`, nach notes_ai, RTC-RAM-Back-off, NVS-Toggle `pcas`) macht je Standby **nur EINEN** Feed (Round-Robin), damit das WLAN kurz bleibt. Wiedergabe via Audio-Queue (Owner Podcast), Resume-Position als NVS-Bookmark (`crc32(pfad)`, wie book_app). Konsole `podcast`/`podcast feed <url>`/`podcast rm <idx>`/`podcast on|off`/`podcast sync`.
- `services/library.*` — Musik-Bibliothek `/music`, **kein Track-Limit**: Tracks liegen in bedarfsbasiert wachsenden PSRAM-Blöcken (`TRACK_BLOCK`=512, Hartgrenze `TRACKS_HARD_MAX` nur als Überlauf-Schutz mit Log-Warnung); sortiert wird eine Permutation, nie die Blöcke. Boot lädt `/.fennek/tracks.bin` (komplette Bibliothek inkl. Tags, Sekunden statt Verzeichnis-Walk); ohne Cache läuft `startScan()`+`scanStep()` im Hintergrund (readdir via `getNextFileName`, kein fopen — Lektion vom Bücher-Scan; max. 6 Einträge pro spiLock). Dateigrößen trägt der Tag-Scan beim Öffnen nach (`id3::Tags.fsize`). Pfade bis `TRACK_PATH_LEN`(256); längere werden geloggt und übersprungen (Calibre-Pfade sprengten 192 → unauffindbare Phantom-Tracks). Künstler/Album/Playlist-Indizes, ID3-Anwendung + Cache (CRC-Binärsuche, gechunkte Reads/Writes), `indexOfPath`, inkrementeller `tagScanStep`.
- `services/id3.*` — minimaler ID3v1/v2-Reader (TIT2/TPE1/TALB, UTF-16/Latin-1→UTF-8, Frames werden ge-seekt, nicht gelesen).
- `services/gps.*` — minimaler NMEA-0183-Empfänger fürs T-Deck-Pro-GPS (**u-blox MIA-M10Q**, UART1 38400, Maps-App). `begin()/end()` schalten das Modul über `board::gpsPower()`, `poll()` liest UART1 zeilenweise und parst `$..GGA`/`$..RMC` (Fix-Qualität, Sats, HDOP, Höhe, Position, Speed, UTC; Checksumme geprüft). UTC wird aus RMC schon **vor** dem Positionsfix übernommen (Datum+Zeit genügen). **Schnellerer Fix:** `begin()` injiziert per UBX-MGA-INI-TIME_UTC die bekannte Systemzeit und (falls `settings::meshPos` gesetzt) per UBX-MGA-INI-POS_LLH die grobe Position — der Empfänger sucht dann gezielt statt kalt (Az/El der Sats sofort da). Kein TinyGPS++; `parseLine()` Arduino-frei/host-testbar. `Fix` via `current()`.
- `services/maps_tiles.*` — SD-Raster-Kacheln + Slippy-Map-Mathematik (Web-Mercator). Kacheln liegen 1-bit-gepackt unter `/maps/{z}/{x}/{y}.bin` (256×256, MSB zuerst, 8192 B; Bit=schwarz) und werden mit `drawBitmap` geblittet — kein PNG-Decoder. **PSRAM-Kachel-Cache** (16 Slots, LRU): `ensureViewport()` lädt fehlende Kacheln **unter eigenem `spiLock`, gechunkt** (nur aus `tick()`!), `blitViewport()` kopiert lock-frei aus dem Cache (aus `draw()`). `scanZooms()` ermittelt die vorhandenen Zoomstufen. Kacheln erzeugt `tools/maps_tiles.py` (OSM-PNG→Dither→`.bin`) am PC.
- `services/textdoc.*` — Streaming-Paginierung mit Seiten-Offset-Index (Cache `/.fennek/idx/`); Indexer und Renderer teilen denselben Umbruch-Code (host-getestet).
- `services/epubzip.h`/`epubproc.*` — EPUB→TXT (ROM-tinfl, OPF-Spine, XHTML-Strip → reines UTF-8), inkrementell, Cache `/books/.epub_cache/`.
- `apps/launcher.*` — Kachel-Grid (2 Seiten à 2×5 = 20 Plätze, flache Kacheln), Now-Playing-/Resume-Zeile. Leere Plätze (Label `None`) werden übersprungen; Seitenwechsel per Touch-Pfeile bzw. A/D am Spaltenrand. Belegt: Seite 1 = Musik/Hörbuch/Lesen/Mesh/Optionen/Spiele/Dateien/Notizen/Wecker/Karten, Seite 2 = Lage/Rechnen/Lernen/Podcast.
- `services/alarmclock.*` — Wecker-Engine (Gerät hat keinen HW-RTC, nutzt die Deep-Sleep-feste Systemzeit). Bis zu 4 Wecker (NVS-Namespace `alarm`, dowMask=0=täglich, sonst Bit0=Mo…), Schlummer (RTC-RAM, übersteht Schlaf). Klingeln: lauter **Piepton** (einmalig generiertes `/.fennek/alarm.wav`, 2,5-kHz-Rechteck-Beep/Pause-Muster) bei **voller Lautstärke** (gemerkt + beim Quittieren zurückgesetzt) über die Audio-Queue (Owner Music, Repeat One) — eigener Klingelton via `alarm sound <pfad>` überschreibt den Piepton; dazu blinkt das **Tastatur-Backlight** (GPIO42, `PIN_KB_BL`; auf Boards ohne Backlight gefahrlos wirkungslos). **Signal-Modus pro Wecker** (Feld `Alarm.signal`, in die NVS-Packung als byte0-Bits1-2 codiert; 1=Ton, 2=Blinken, 3=beides; Altdaten=0→beides) gatet Ton/Blinken für den jeweils klingelnden Wecker. Auto-Quittung nach 5 min. Konsole `alarm <i> mode ton|blink|beides`. `poll()` im `loop()` löst minutengenau aus (entprellt; klingelt nie bei ungestellter Uhr). `nextDueEpoch()` füttert die Wake-Berechnung in `core/power`. Konsole `alarm`, App `apps/alarms_app`.
- `apps/music_app.*` — Browser (Künstler/Album/Playlist, Bucket-Gruppierung) + Player (Mix/Wdh/Zzz). Tasten: W/S/Enter/Backspace, A/D, X/R/Z, P, Q=Home.
- `apps/book_app.*` — Hörbücher aus `/audiobooks` (Ordner=Buch, Natural-Sort), NVS-Bookmarks (30 s + bei Pause/Leave/Eviction), ±30 s, Sleep-Timer.

## Funkparameter

Default = **„EU/UK Narrow“** (Standard in Deutschland/NRW, identisch zu Daniels Repeater in `../meshcore_bridge_repeater/`): **869,618 MHz, BW 62,5 kHz, SF 8, CR 4/5**, 22 dBm, DIO2-RF-Switch, TCXO 2,4 V. Die platformio.ini-Flags sind nur Compile-Defaults; maßgeblich sind die NVS-Werte (`settings::meshParams()`), einstellbar in der Settings-App („Optionen“-Kachel, zweistufige Kategorie-Navigation: Wurzel = Ordner **Funk / System / Zeit / WLAN / Navidrome / Ollama**, Auswahl öffnet die Zeilen; im Ordner „Funk“ Preset EU Narrow/EU Klassisch oder Einzelwerte + Node-Name) und live angewandt via `mesh_client::applyRadioParams()`. Achtung Falle: `initContacts()` MUSS in `MeshClient::begin()` gerufen werden (PSRAM-Deferral des Meck-Forks), sonst crasht der erste empfangene Advert (NULL-`contacts`).

**Drei am Gerät gefundene, gefixte Fallen (nicht reintroduzieren!):**
1. `initContacts()` muss in `MeshClient::begin()` gerufen werden — sonst NULL-`contacts`-Crash beim ersten Advert.
2. **Kein `spiLock()` aus Code, der schon unter dem Lock läuft** — nicht-rekursiver Mutex → Self-Deadlock; das Gerät friert komplett ein (Loop, Touch, Tastatur UND Serial-Konsole tot, kein Watchdog-Reset). Zweimal passiert: (a) `logToSd` direkt aus `pushMsg` (Mesh-Loop hält das Lock; Lösung: `s_needLog[]` + `flushLog()` nach `spiUnlock()` in `mesh_client::loop()`); (b) 12.06.2026: `readIdentityFile` nahm spiLock, läuft aber via `MeshClient::begin()` bereits unter dem Lock aus `mesh_client::begin()` — jedes Betreten der Mesh-App fror mit gesteckter SD ein. Merke: `MeshClient::begin()` und alle Mesh-Callbacks laufen unter spiLock; ebenso `App::draw()` (innerhalb `display::render`).
3. **RTC-Sync**: Kein Hardware-RTC → Uhr aus Advert-Timestamps in `onDiscoveredContact` syncen (`RTC=`/`Quelle=` im `status`, Details über `time`). **Nicht blind vorwärts ratschen** — ein Node mit Zukunfts-Uhr zog uns am 12.06.2026 um +28 h mit. Regeln: Vorwärts-Korrektur < 1 h, Rückwärts nur bei 3 Adverts in Folge > 1 h hinter uns. **Override-Falle gelöst (13.06.2026):** ein einmaliger `s_clockConfident`-Bootstrap erlaubt dem **ersten** plausiblen Advert seit Boot/NVS-Restore einen beliebig großen Vorwärtssprung (sonst fror eine >1 h zurückliegende Restore-/Wake-Zeit unter dem 1h-Deckel ein). **Deep-Sleep-Falle gelöst (13.06.2026):** die alte `millis()`-basierte `VolatileRTCClock` verlor beim Deep Sleep die **gesamte Schlafdauer** (Wake = Neustart, `millis()`=0, Uhr zurück auf Mai 2024). Seither = ESP32-Systemzeit (`SystemRTCClock`), die den Schlaf übersteht; Koordination/NTP/Persistenz/Zeitzone in `services/timesync.*`.
4. **Kontakt-Tabelle voll (MAX_CONTACTS=64)**: Neue Adverts wurden still verworfen — neue Nodes tauchten nie auf. Fix: `shouldOverwriteWhenFull() = true` in `MeshClient` (ältester Nicht-Favorit wird ersetzt).
5. **Auto-Standby kennt Konsole nicht**: Serielle Mesh-Tests starben alle ~5 min im Deep Sleep. Fix: `power::noteActivity()` in `console::handleLine()`.

Hinweis: `gpio_install_isr_service already installed` beim Mesh-Init ist harmlos. Konsole kann Hashtag-Kanälen beitreten (`join test`, `chan test <txt>`) — **`public #test …` landet dagegen im Public-Channel, wo Kanal-Bots nicht zuhören**. **DM mit ACK end-to-end bestätigt (12.06.2026):** DMs an Antonia/Echobot (eigene Nodes, Web-Client `meshcore.dumke.me`) `[zugestellt]`, Echobot-Echo + Gegenrichtung empfangen, #wetter-Bot antwortete im Kanal. **SD-Persistenz verifiziert (12.06.2026):** `join test`/`join wetter` → RTS-Reset → nach `mesh init` Kanäle `[1] #test [2] #wetter` und Kontakte=64 wieder da; `/meshcore/contacts.bin` (8960 B = 64×140) + `channels.txt` auf SD. **Noch offen:** Hörbuch-Resume, EPUB am Gerät, Touch meldet bei gehaltenem Finger Dauer-Taps (kosmetisch, `[APP] Tap`-Spam im Log).
